# 競馬AIプロジェクト 外部AI向け固定前提

更新日: 2026-06-29

この文書は、外部AIに相談する前に読み込ませるための固定前提です。
目的は、毎回「特徴量を増やす話」から始めず、現在のモデル構造・検証思想・未解決課題を共有した状態で助言を受けることです。

## 1. プロジェクトの目的

この競馬AIの目的は、予測精度そのものではなく、長期的な回収率の最大化です。

重要度は以下です。

1. 長期OOSで回収率を維持できること
2. 買うべきでないレースを見送れること
3. 直前オッズを含めた実運用で再現できること
4. 馬券種・買い目・金額配分まで含めて期待値が残ること
5. 単なる的中率やAUCの改善だけを目的にしないこと

回収率が下がる特徴量・ロジックは、予測精度が上がっても採用しない。

## 2. 現在の主戦略

現在の本線は「最強版AI」の厳選馬連中心戦略です。

主な考え方:

- すべてのレースを買わない
- AI評価、オッズ妙味、前目確率、ペア確率、危険人気馬、レース難易度を組み合わせて最終BUYを絞る
- ワイド・単勝・3連複なども検討したが、現在の本線は馬連中心
- 参考・注視・強め見送り・シャドー候補は記録するが、正式BUYとは分ける
- 出走後に判定が変わっても、出走前スナップショットを正とする

現状の代表的な検証値:

- ベース最強版: 217点 / 191R / ROI 375.9%
- 能力下限フィルター後: 180点 / 157R / ROI 426.8%
- 時計相対順位 + 能力下限: 143点 / 126R / ROI 459.4%
- 時計精査上位 + 能力下限: 35点 / 31R / ROI 716.4%

注意:

- ROIが高い条件ほど点数が少なく、過学習・上振れリスクがある
- 2026単年のサンプルはまだ薄い
- 高ROI条件は即採用ではなく、シャドー運用で継続確認する

## 3. 採用済みまたは実装済みの主要特徴量

すでに多くの特徴量を実装済みです。外部AIには「一般的な特徴量を追加せよ」ではなく、どの特徴量をどう選別・較正・組み合わせるかを相談したいです。

## 4. 現在の運用構成

主なスクリプト:

- `scripts/run_current_strongest_line_update.ps1`
  - 当日更新の主パイプライン
  - オッズ、馬体重、馬場、買い目、ダッシュボード、LINE通知に関係
- `scripts/build_current_strongest_tickets.py`
  - 最強版の買い目生成
  - 正式BUY、強め見送り、注視、シャドー候補の中核
- `scripts/enrich_prediction_basic_ability_features.py`
  - 予測CSVへ基礎能力・時計精査特徴量を追加
- `scripts/evaluate_time_value_refinement_features.py`
  - 時計価値の外部AI助言を検証したスクリプト

ダッシュボード:

- ローカルHTTPで閲覧
- 外部URL化も可能
- スマホ操作を想定
- 最新取得ボタンで更新
- レース別更新と全体更新を分離
- LINE通知は8時、発走前5分、必要に応じて3分前を想定

## 5. 検証ルール

外部AIに助言を求める際は、以下を必ず守る。

### 採用条件

- 実運用時点で取得できる情報だけを使う
- 出走後情報を特徴量に使わない
- 出走後の再計算で出走前判定を上書きしない
- T-5/T-3など、購入可能時点のスナップショットで検証する
- 年度別ウォークフォワードで確認する
- 可能なら purged walk-forward / MCS / PBO で確認する
- ROIだけでなく、点数、購入レース数、的中率、最大ドローダウン、年度別ROIを見る
- 少数の大当たり依存を確認する
- 閾値を少し動かしても壊れないか確認する

### 不採用または保留条件

- ROIが下がる
- 点数が極端に減りすぎる
- 2026や直近OOSで弱い
- 1開催場・1配当に依存している
- データリークの疑いがある
- 説明は良いが、実運用タイミングで取得できない
- 複雑化する割に買い目判断に効かない

## 6. 現在の重要課題

外部AIに聞きたいのは主に以下です。

1. 馬連ペア精度の飛躍的改善
2. 準候補を安全に正式BUYへ昇格させる条件
3. T-5/T-3時点で妙味が残る馬券の見極め
4. 展開が読めているのに馬が違うのか、展開そのものを外しているのかの分解
5. 先行有利/差し有利を単純化せず、コース・馬場・ペース・隊列で精緻化する方法
6. 経験不足馬、初条件馬、人気のある新馬勝ち馬の扱い
7. 時計価値・ラップ価値を馬券ペア選択にどう落とすか
8. 血統を単なるタグではなく、条件適性・価格差発見に使う方法
9. 買い目候補を増やしすぎず、準候補の中から昇格できるものを見つける方法
10. 高ROI条件の過学習・上振れをどう見抜くか

## 7. 外部AIへ相談するときの基本プロンプト

以下を先頭に付ける。

```
あなたは競馬AIの回収率最大化アドバイザーです。
このプロジェクトの目的は予測精度ではなく、実運用可能な馬券回収率の最大化です。
特徴量追加ありきではなく、買う/見送る/シャドー運用する判断を重視してください。
必ず、実運用時点で取得できる情報だけを使う前提で考えてください。
データリーク、過学習、少数の大当たり依存、点数減少、直前オッズ取得可能性を必ずチェックしてください。
すでに多数の特徴量は実装済みなので、一般論ではなく、どの特徴量・フィルター・買い目変換が弱いかを診断してください。
```

## 8. 外部AIへの回答で特にほしい形式

外部AIには、以下の形で返答してもらうと実装しやすい。

1. 仮説
2. その仮説が効く理由
3. 必要な入力データ
4. データリークの危険
5. 実装する特徴量
6. 買い目判定への落とし込み
7. 検証方法
8. 採用条件
9. 不採用条件
10. 優先度

## 9. 現時点での方針

今は、正式BUYを安易に増やす段階ではない。

優先順位:

1. 出走前スナップショットの固定
2. 準候補シャドー運用の蓄積
3. 馬連ペア確率の改善
4. 時計・ラップ・展開のレース質精査
5. 危険人気馬と妙味残存の改善
6. 血統・調教・厩舎の細分化は、回収率に効くものだけ採用

最終的には、以下の構造を目指す。

- 強い馬を当てるモデル
- 前に行ける/差せる展開適性モデル
- ペアで同時に来る確率モデル
- 直前オッズで妙味が残るかのモデル
- 買わないレースを見送るモデル

この5層を分けて考える。
